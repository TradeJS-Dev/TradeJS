# Применимые правила качества кода

Это отбор принципов из исторического справочника DevHub, проверенный на
границах TradeJS. Локальные решения отдельных чужих обсуждений, номера MR,
частные исключения сборщика и требования конкретного UI не являются нормами
этого проекта. Приоритет имеют задача, `AGENTS.md`, текущие контракты и код.

- **Границы.** Найди потребителей общего кода и допустимое направление
  зависимости. UI и инфраструктура не попадают в browser-safe `core`.
  Используй публичные subpaths и локальные `imports` по
  [карте проекта](tradejs-context.md), избегай обратного импорта собственного
  barrel. Новая сущность скрывает самостоятельную обязанность.
- **Типы.** Бери тип у владельца контракта. Различай вход, нормализованную
  модель и ответ. Не маскируй несовместимость `any`, двойным `as` или `!`.
  Для внешнего неизвестного входа используй `unknown` и сужение/валидатор.
  Недопустимые сочетания состояний выражай типами, если это упрощает контракт.
  Не вводи всеобщий запрет `type` или требование `interface` из чужого проекта.
- **Сохранение поведения.** Перенос и типизация не отменяют прежние defaults,
  преобразования и побочные эффекты. Выбирай `||` или `??` по смыслу `0`,
  `false`, пустой строки и отсутствия. Учитывай поддерживаемые входы;
  не добавляй неподтверждённые режимы совместимости.
- **Асинхронность.** Поздний ответ, `catch` и `finally` старого запроса не
  меняют более новое состояние. Различай начальную и фоновую загрузку;
  spinner не должен порождать цикл unmount → запрос → spinner. Ошибка записи
  передаётся вызывающему коду, успех показывается только после успеха.
  После `Promise.allSettled` оцени результаты обязательных операций.
  Отмена не приравнивается к любой ошибке.
- **Владение данными.** Общие представления одной сущности читают согласованный
  источник. Не копируй props в state без причины. Ключ кеша отражает параметры
  результата. Не мутируй входной объект, если контракт этого не разрешает;
  глубокая копия всего графа тоже не нужна по умолчанию.
- **Читаемость.** Имена объясняют предметный смысл. Комментарий поясняет
  неочевидную причину. Не добавляй файл констант ради одного литерала или
  универсальный runner ради нескольких понятных шагов. Изменяемый генератор
  не должен без причины переписывать тот же файл и запускать watcher снова.
- **Покрытие.** Проверяй настоящий код, результат и значимые эффекты, а не
  displayName, буквальное значение CSS или работу моков. Для геометрии нужен
  реальный браузер. Правила выбора и моков находятся в
  [качестве тестов](../../task-unit-test-coverage/references/test-quality.md).

В замечании укажи файл, строку, сценарий поломки и минимальное исправление.
Отделяй подтверждённый дефект от предпочтения дизайна. Для исторического
совета объясни совпадение условий; факт merge не доказывает общую норму.
Не публикуй секреты и частные обсуждения как часть инструкций.
