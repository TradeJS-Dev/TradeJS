# Композиция React-компонентов

Цель — понятный контракт компонента при сохранении поведения потребителей.
В `apps/app` используются React `19.2.8`, Next.js `16.2.11` и
Chakra UI `3.36.1`. Сначала сверяй текущую конфигурацию и
[границы приложения](../task-planning/references/tradejs-context.md).

- Независимые `disabled`, `loading`, `checked` не требуют перестройки.
  Взаимоисключающие режимы сравни с типизированным `variant`, явными
  компонентами вариантов или `children`; выбирай самый простой полный API.
- Составные компоненты и контекст нужны, когда части действительно делят
  состояние и нужны разные расположения. Для фиксированной формы props и
  `children` часто достаточны. Не вводи provider без общего потребителя.
- Держи состояние у ближайшего подходящего владельца. Не копируй props в
  state ради композиции и не заменяй существующий Zustand store автоматически.
- Отделяй UI-контракт от хранения, когда разные реализации действительно
  нужны. `state/actions/meta` — возможная форма, а не обязательный шаблон.
- Сохраняй render prop, если потребителю нужны вычисленные данные; для
  статического содержимого достаточно `children`. До изменения общего API
  найди всех потребителей, включая независимую установку пакета.
- React 19 не требует массовой замены работающих `useContext`,
  `Context.Provider` и `forwardRef`. Сохраняй принятый совместимый контракт.
  Новый API сверяй с версией и документацией по `AGENTS.md`, а не переноси
  ограничения React 18 или рецепт из чужого примера.

При выборе решения прочитай [варианты и состояние](references/patterns.md).
Проверяй действия, обновления, независимость экземпляров, фокус, ref и
disabled/loading там, где это входит в контракт. Не проверяй внутреннее дерево
компонентов вместо поведения. Для фокуса и геометрии используй настоящий
браузер по [правилам покрытия](../task-unit-test-coverage/references/browser-coverage.md).

В результате укажи выбранного владельца, совместимость и фактические проверки.
Отличие стиля само по себе не дефект. Навык не расширяет права на публикацию
или изменение внешних систем.
