# React и производительность приложения

Начни с пользовательского сценария и пути данных. В `apps/app`
используются React `19.2.8`, Next.js `16.2.11`, Zustand `5.0.14`; сверяй
[снимок проекта](../task-planning/references/tradejs-context.md) с текущими
файлами. Не ограничивай Next.js клиентскими рецептами исходной адаптации
для React 18 и не переноси серверные рецепты в клиент без проверки границы.

1. Подтверди причину: зависимые ожидания по коду, повторные запросы по сети,
   лишние подписки или дорогой рендер по измерению. Выбери относящиеся к задаче
   [клиентские правила](references/client.md); для серверного пути прочитай
   [границы Next.js](references/nextjs.md).
2. Сохраняй ошибки, отмену, актуальность ответа, порядок побочных эффектов,
   изоляцию пользователей и публичный контракт. Меньше рендеров не оправдывает
   смену поведения. Не оптимизируй весь пакет из-за одного компонента.
3. Сравни один сценарий до/после на сопоставимых данных. Регрессионный тест
   подтверждает корректность; ускорение требует измерения. Без него эффект
   остаётся гипотезой, а не достигнутым результатом.

Не добавляй `memo/useMemo/useCallback`, кеш, SWR, виртуализацию или dependency
по умолчанию. Сначала найди имеющиеся средства и реальную стоимость.
Не обходи публичные `exports` ради уменьшения bundle. Не включай новый
компилятор или экспериментальный API только потому, что установлен React 19.
Новые библиотечные API проверяй по Context7 согласно `AGENTS.md`.

Проверки выбирай по [качеству тестов](../task-unit-test-coverage/references/test-quality.md).
Падение из-за окружения не исправляй ослаблением теста. Сообщи подтверждённую
причину, изменение, фактическую проверку и ограничения измерений. Навык не
разрешает публикацию, нагрузку на production и изменение внешних систем.
