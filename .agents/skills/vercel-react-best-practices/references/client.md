# Клиентские запросы, эффекты и рендеринг

## Запросы

Независимые чтения можно начинать параллельно, если нет зависимости, общего
изменяемого состояния и требования последовательности. Зависимый запрос
ждёт входные данные. `Promise.all` не отменяет остальные запросы при отказе;
сохраняй требуемые частичные результаты, отмену и обработку ошибок.
Записи и торговые операции не параллелятся по аналогии с чтениями.

Проверь поздний ответ после смены параметров или unmount. Старые success,
catch и finally не должны менять новые данные или loading. Пример имеющейся
проверки — `apps/app/src/app/routes/derivatives/__tests__/useDerivativesDashboard.test.tsx`.
Не добавляй глобальный кеш для устранения локальной гонки.

## Эффекты и состояние

- Дешёвое производное значение вычисляй при render, не дублируй props в state.
- Обновление от прошлого значения использует функциональный updater, если это
  нужно контракту. В updater нет побочных эффектов: он может быть вызван снова.
- Событие пользователя обрабатывай в обработчике, синхронизацию с внешним
  ресурсом — в effect. Учитывай также обновление извне.
- Зависимости effect отражают реально читаемые значения. Не удаляй их ради
  меньшего числа запусков. Разделяй несвязанные синхронизации, сохраняя
  значимый порядок.
- Подписке нужен cleanup того же ресурса/обработчика. Учитывай повторный
  setup/cleanup. Не вводи глобальную дедупликацию без подтверждённых дублей.
- Ref подходит для значения без влияния на вывод; видимое состояние остаётся
  состоянием. Zustand-подписка должна читать нужную часть store по принятым
  соглашениям; не переписывай store по внешнему рецепту.

## Рендеринг и загрузка

Не определяй тип компонента заново в render другого компонента: это может
сбросить состояние и фокус. Сохраняй `key` и идентичность компонентов.
Для числового условия исключай случайный вывод `0` явным условием.

Перед memo локализуй состояние и зависимости. Новая ссылка массива или
callback важна только если влияет на поведение либо стоимость. Не усложняй
понятные проходы данных без измеренной причины.

Для тяжёлой необязательной ветки оцени существующую ленивую загрузку и
проверь fallback/ошибку. Для больших списков найди существующий `react-window`
или иной механизм проекта, измерь стоимость и проверь фокус/скролл.
Не выводи универсальный порог по числу элементов.

Проверяй смену параметров, поздние ответы, повторное подключение и очистку
ровно там, где они входят в риск задачи. Работа с браузерным chart/IndexedDB
не должна случайно выполняться на сервере. Детали — в
[границах Next.js](nextjs.md). [Происхождение](upstream.md).
