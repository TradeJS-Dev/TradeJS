# Границы Next.js в TradeJS

Это дополнение TradeJS к клиентской адаптации Vercel. Проверяй текущий код
Next.js `16.2.11`, а новые API — по правилам документации в `AGENTS.md`.

- Найди фактическую цепочку: `apps/app/src/app/routes`, клиентский store,
  `app/actions`, `app/api`, серверные `@tradejs/node/*` и `@tradejs/infra/*`.
  Одинаковое название функции не доказывает, где она выполняется.
- Сохраняй серверную границу секретов, авторизации и доступа к данным.
  Серверное действие или endpoint проверяет пользователя самостоятельно;
  скрытая кнопка не является авторизацией.
- Не протягивай Redis, Node-only API и секретные значения через props в
  клиентский bundle. Общий `core` остаётся браузерно-безопасным.
- Параллель независимых серверных чтений допустима при сохранении ошибок и
  изоляции пользователя. Не вводи общий кеш пользовательских runtime-данных
  без контракта ключей, актуальности и invalidation. Не считай данные
  автоматически кешируемыми по совету для другой версии Next.js.
- При SSR/hydration сохрани согласованность исходных данных и браузерных
  зависимостей. `provider.tsx` задаёт Chakra, тему и сессию; не лечи проблему
  полной клиентской отрисовкой всех страниц без установления причины.
- После изменения серверно-клиентской границы проверь типы и сборку, а
  пользовательское поведение — подходящим тестом. Успешный jsdom-тест с
  подменённым router/provider не доказывает hydration или серверную защиту.

Не предписываются новый cache, Server Actions, Suspense, dynamic import или
React 19 API без задачи. [Происхождение дополнения](upstream.md).
